Auto-instrument - Rancher k3s prerequisites

This path swaps podman run for a local Rancher Desktop k3s cluster. Make sure you have Podman v5+ to build the image, plus Rancher Desktop with the Kubernetes (k3s) engine enabled, and kubectl on your PATH.

Auto-instrument - Start Rancher Desktop

This lab assumes Rancher Desktop is installed but not yet running. Launch it now: 
							
								$ rdctl start
  • Open the Rancher Desktop application
  • In Preferences → Kubernetes, confirm "Enable Kubernetes" is checked (k3s)
  • Also check Container Engine, confirm "containerd" is checked
  • Wait for the status indicator in the bottom left to turn green and show "Kubernetes is running" - this can take a minute or two on first start

Auto-instrument - Verifying tooling installation

Before diving in, confirm your cluster is actually up and kubectl is pointed at it (note versions shown might differ for you): 
							
								$ kubectl config current-context
								rancher-desktop

								$ kubectl get nodes
								NAME                   STATUS   ROLES                  AGE   VERSION
								lima-rancher-desktop   Ready    control-plane,master   2d    v1.36.2+k3s1
Now that you have the tooling, let's get started...

Auto-instrument - Getting started

For applicable languages, OpenTelemetry provides a way to auto-instrument your application without making code changes by adding the API and SDK to the application and any detected instrumentation libraries and exporter dependencies.

We are working with a Python Flask app in this workshop and Python dynamically injects bytecode to capture telemetry from popular libraries and frameworks.

Let's see what we can get out-of-the-box!

Auto-instrument - Make a project directory

Open a console or terminal window and create an empty workshop directory to work in like: 
							
								$ mkdir workshop-opentelemetry

								$ cd workshop-opentelemetry

Auto-instrument - Download demo application

  • Click to download and unzip the project.
  • Move into the project directory and build the image as shown:
							
								$ cd intro-to-instrument-VERSION

								$ podman build -t hello-otel:base -f Buildfile
Verify you get a success message in the console like below: 
							
								...
								Successfully tagged localhost/hello-otel:base  \
								516c5299a32b68e7a4634ce15d1fd659eed2164ebe945ef1673f7a55630e22c8

Auto-instrument - Import the image into k3s

Podman built the image locally, but k3s runs inside Rancher Desktop's own VM with a separate containerd image store - there's no k3s binary on your host, so use the nerdctl CLI Rancher Desktop installed on your PATH to load the image straight into the VM's k8s.io namespace where kubelet looks for it: 
							
								$ podman save localhost/hello-otel:base -o hello-otel-base.tar

								$ nerdctl --namespace k8s.io load -i hello-otel-base.tar

								unpacking localhost/hello-otel:base (sha256:560d1e0ad0cfda2e8bdf0fccb7524cce8c983bba61fa7f1b12510a4b1ccd1e16)...
								Loaded image: localhost/hello-otel:base
Note: if nerdctl fails with "cannot access containerd socket", your Container Engine is set to dockerd instead of containerd - either switch it in Preferences, or use docker load -i hello-otel-base.tar for every import in this lab.

Auto-instrument - Run on k3s

Run the image as a pod, mapping container port 8000 the same way the Podman path maps to local port 8001, this time with kubectl port-forward. Note the image name must match exactly what was loaded - localhost/hello-otel:base, not just hello-otel:base - or --image-pull-policy=Never can't find it. The delete --ignore-not-found clears out any pod left over from a previous attempt so re-running this is safe: 
							
								$ kubectl delete pod hello-otel --ignore-not-found

								$ kubectl run hello-otel --image=localhost/hello-otel:base --image-pull-policy=Never \
								  --port=8000 --env="FLASK_RUN_PORT=8000"

								pod/hello-otel created

								$ kubectl port-forward pod/hello-otel 8001:8000
								Forwarding from 127.0.0.1:8001 -> 8000
								Forwarding from [::1]:8001 -> 8000
Open http://localhost:8001 in your browser and confirm you see this displayed: 
							
								This webpage has been viewed 1 times

Auto-instrument - Instrument traces

Open automatic/Buildfile-auto which installs packages and updates the run command for auto-instrumentation:

  • opentelemetry-distro[otlp] - contains the API, SDK, opentelemetry-bootstrap, opentelemetry-instrument
  • opentelemetry-bootstrap - installs instrumentation libraries corresponding to installed packages
  • opentelemetry-instrument - agent that dynamically injects bytecode to capture telemetry. Configures a global tracer and by default OTLP exporter

Auto-instrument - Build the image

Build an image from the container file with Podman: 
							
								$ podman build -t hello-otel:auto -f automatic/Buildfile-auto

Auto-instrument - Import OpenTelemetry SDK

Let's add the number of times the homepage has been loaded. Open automatic/app.py and import the OpenTelemetry SDK, which is already installed by opentelemetry-distro: 
							
								import random
								import re
								import urllib3

								import requests
								from opentelemetry import trace
								from flask import Flask, render_template, request
								...

Auto-instrument - Access tracer

To access the auto-instrumented spans we need to get access to the tracer which is responsible for span creation and management.

The opentelemetry-instrument agent creates one automatically, so our code only needs to be responsible for accessing it. 
							
								import random
								import re
								import urllib3

								import requests
								from opentelemetry import trace
								from flask import Flask, render_template, request
								from breeds import breeds

								app = Flask(__name__)
								tracer = trace.get_tracer(app.name)
								...

Auto-instrument - Manually adjust span attribute

We know Flask routes are already instrumented so we need to access the existing span instead of creating a new span. Find the index() method associated with the / route and update to access the auto-instrumented span and add an attribute key-value pair for "hits" and the value stored in HITS: 
							
								@app.route('/')
								def index():
								  span = trace.get_current_span()
									global HITS
									HITS = HITS + 1
								  span.set_attribute("hits", HITS)
									msg = f'This webpage has been viewed {HITS} times'
									return msg
