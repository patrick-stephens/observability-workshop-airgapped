Perses - Kubernetes installation notes

This lab guides you through installing Perses on a local Kubernetes cluster provided by Rancher Desktop, an open source desktop application that ships a lightweight Kubernetes distribution (k3s) and works on Mac OS X, Linux, and Windows systems. This workshop assumes you have installed and started it with Kubernetes enabled in the preferences:

  • Install Rancher Desktop (Mac OS X, Linux, or Windows)
  • Install the Helm command line tooling


The rest of this lab is pictured using Mac OS X, but it is assumed you have enough knowledge of your Linux or Windows systems to be able to achieve the same results. Also note that any other local Kubernetes cluster works here (minikube, kind, Docker Desktop), but we leave you to sort out the details.

Perses - Verifying tooling installation

To start with a working Kubernetes installation, you should see the following results for the commands shown (note versions shown might differ for you): 
							
								$ kubectl config current-context
								rancher-desktop

								$ kubectl get nodes
								NAME                   STATUS   ROLES                  AGE   VERSION
								lima-rancher-desktop   Ready    control-plane,master   2d    v1.33.3+k3s1

								$ helm version
								version.BuildInfo{Version:"v3.x"}  <<<< MINIMUM VERSION REQUIRED
Now that you have the tooling, let's get started installing Perses on Kubernetes...

Setup - Adding the Helm repository

The Perses project publishes an official Helm chart. Add the repository, refresh it, and confirm that the chart version you are about to install ships the Perses version this workshop is built on: 
							
								$ helm repo add perses https://perses.github.io/helm-charts
								"perses" has been added to your repositories

								$ helm repo update
								...
								...Successfully got an update from the "perses" chart repository
								Update Complete. ⎈Happy Helming!⎈

								$ helm search repo perses/perses --version 0.23.2
								NAME           CHART VERSION  APP VERSION  DESCRIPTION
								perses/perses  0.23.2         v0.54.0    Perses helm chart

Installation - Deploying the Helm chart

Now you can install Perses into its own perses namespace. We use helm upgrade --install instead of helm install so that this exact command keeps working whether it is the first time you run it or the tenth: 
							
								$ helm upgrade --install workshop-perses perses/perses \
								    --version 0.23.2 \
								    --namespace perses --create-namespace

								Release "workshop-perses" does not exist. Installing it now.
								NAME: workshop-perses
								LAST DEPLOYED: Tue Aug 25 13:04:49 2026
								NAMESPACE: perses
								STATUS: deployed
								REVISION: 1
								DESCRIPTION: Install complete

Installation - A note on names

Naming the release workshop-perses matters. The chart collapses the name when the release already contains "perses", so our resources land as workshop-perses instead of the rather silly workshop-perses-perses. Every command in this lab passes -n perses explicitly. If you get tired of typing it, you can make that namespace your default: 
							
								$ kubectl config set-context --current --namespace=perses

Installation - Verifying the deployment

Give it a few seconds and check that the pod is running and the service is there. The exact pod name suffix will differ for you: 
							
								$ kubectl get pods -n perses

								NAME                READY   STATUS    RESTARTS   AGE
								workshop-perses-0   1/1     Running   0          42s

								$ kubectl get svc -n perses

								NAME              TYPE        CLUSTER-IP    PORT(S)    AGE
								workshop-perses   ClusterIP   10.43.74.55   8080/TCP   42s

Installation - Start your dashboard engines!

The service is a ClusterIP, which means it is only reachable from inside the cluster. Forward it to your machine so that the rest of this workshop can reach Perses on the same localhost:8080 that every other installation path uses. Leave this running in its own console window for the rest of the workshop: 
							
								$ kubectl port-forward -n perses svc/workshop-perses 8080:8080

								Forwarding from 127.0.0.1:8080 -> 8080
								Forwarding from [::1]:8080 -> 8080

Examples - An empty Perses is a boring Perses

What you are looking at is a completely empty Perses server. The container installation path arrives preloaded with a workshop project and two example dashboards, and you want the same starting point here.

You load them with percli, the Perses command line tool, which you will meet properly in the next lab. The installation project ships both the tool and the example files, so download and unzip it now:
download the project.

Examples - Doing it the easy way

The installation project can do everything in this lab for you. If you would rather not run the Helm and kubectl commands by hand, stop your port-forward, delete the namespace, and let the script do the work instead: 
							
								$ kubectl delete namespace perses

								$ ./init.sh rancher
It installs the chart, waits for the pod, starts the port-forward in the background, and loads the examples. Note that init.bat does not support this mode, so on Windows follow the commands in this lab by hand.

Examples - Loading them by hand

If you prefer to do it yourself, unzip the percli tool for your machine and log in to the Perses instance you just forwarded (from the project directory): 
							
								$ unzip support/bin/percli-darwin-amd64.zip -d support/bin/

								$ cd support

								$ ./bin/percli login http://localhost:8080

								successfully logged in

Examples - Applying the workshop project

Now apply the workshop project, the example dashboard, and the Prometheus data source. These are the exact same files the container installation path loads for you: 
							
								$ ./bin/percli apply -f workshop-project.json

								$ ./bin/percli apply -f workshop-myfirstdashboard.json

								$ ./bin/percli apply -f workshop-datasource-prometheusdemolocal.json

								$ ./bin/percli apply -f data/globaldatasource.json

Intermezzo - Why localhost still works

You might be wondering how a data source pointing at http://localhost:9090 is going to work when Perses is running inside a Kubernetes pod, where localhost means the pod itself.

The answer is that this workshop uses a directUrl data source, which means your browser issues the queries, not the Perses server. As long as Prometheus is reachable on localhost:9090 from the machine your browser is running on, it works exactly the same on every installation path in this workshop. You will set that up in lab 5.

Kubernetes - Cleaning up later on

You do not need this yet, but when you are completely finished with the workshop, stopping the port-forward and deleting the namespace removes the Helm release, the Perses server, and everything else this lab created: 
							
								$ kubectl delete namespace perses
Leave it running for now, the rest of the workshop needs it.
