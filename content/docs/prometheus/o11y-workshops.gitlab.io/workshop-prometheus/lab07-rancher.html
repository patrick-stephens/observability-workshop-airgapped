Service discovery - Exercise infrastructure

You'll be setting up the following architecture to support your service discovery exercises using the services demo to ensure your local infrastructure contains the following:

  1. Production 1 reachable at http://localhost:11111
  2. Production 2 reachable at http://localhost:22222
  3. Development reachable at http://localhost:44444


On Kubernetes these are three separate Deployments and Services, each reached locally through its own kubectl port-forward. In-cluster, Prometheus reaches them by their Service DNS names on port 8080, not through these forwarded ports.

Services demo - Building an image the cluster can see

Kubernetes pulls images from a registry, and we never push this one anywhere. The trick is to build it straight into the image store your cluster reads from. Rancher Desktop ships two container engines, so first check which one you are running under Preferences > Container Engine, then use the matching command: 
							
								# Container engine set to dockerd (moby) - k3s reads the docker image store directly.
								#
								$ docker build --load -t prometheus_services_demo:v1 -f installs/demo/Buildfile installs/demo

								# Container engine set to containerd - build into the k8s namespace.
								#
								$ nerdctl --namespace k8s.io build -t prometheus_services_demo:v1 -f installs/demo/Buildfile installs/demo
Same gotchas as before: that trailing installs/demo is the build context, not a typo for ., on containerd the --namespace k8s.io is not optional, k3s only looks in that namespace, and on dockerd a docker-container buildx builder needs --load or the image never reaches docker images.

Services demo - Verifying the built image

Looking up our built image to verify everything went well. Ask for it by name, a bare docker images lists every image on your machine and the one we care about is lost in the noise: 
							
								$ docker images prometheus_services_demo

								IMAGE                         ID             DISK USAGE   CONTENT SIZE
								prometheus_services_demo:v1   d039d73640e2       31.8MB         10.1MB
On a containerd set up the command is nerdctl --namespace k8s.io images prometheus_services_demo.

Services demo - Production 1 manifest

Using any editor you like, create a file named services-demo-prod1.yaml: 
							
								apiVersion: apps/v1
								kind: Deployment
								metadata:
								  name: services-demo-prod1
								spec:
								  replicas: 1
								  selector:
								    matchLabels:
								      app: services-demo-prod1
								  template:
								    metadata:
								      labels:
								        app: services-demo-prod1
								    spec:
								      containers:
								      - name: services-demo-prod1
								        image: prometheus_services_demo:v1
								        imagePullPolicy: IfNotPresent
								        ports:
								        - containerPort: 8080

								---
								apiVersion: v1
								kind: Service
								metadata:
								  name: services-demo-prod1
								spec:
								  selector:
								    app: services-demo-prod1
								  ports:
								  - port: 8080
								    targetPort: 8080

Service discovery - Starting production 1

Deploy it into the prometheus namespace. If you skipped ahead or aren't sure it still exists, this first command is safe to run every time, it creates the namespace only if missing and no-ops otherwise: 
							
								$ kubectl create namespace prometheus --dry-run=client -o yaml | kubectl apply -f -

								$ kubectl apply -f services-demo-prod1.yaml -n prometheus

								deployment.apps/services-demo-prod1 created
								service/services-demo-prod1 created

Service discovery - Testing production 1

Port-forward it to your chosen local port, in its own terminal window, then test at http://localhost:11111/metrics: 
							
								$ kubectl port-forward -n prometheus svc/services-demo-prod1 11111:8080
